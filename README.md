# Portablizer

**Portablizer** — приложение с современным графическим интерфейсом (PySide6/Qt),
которое помогает превратить распространённые **exe/msi-установщики** в
**портативные приложения**, работающие прямо из папки.

Portablizer запускает **тихую установку с перенаправленным пользовательским
окружением** в указанную папку, проверяет фактический результат и учитывает
локальные зависимости и переменные среды. Полная виртуализация Windows не
выполняется, поэтому совместимость зависит от конкретного установщика и
приложения.

![Интерфейс Portablizer](docs/preview.png)

## Что делает

1. **Определяет тип установщика** по сигнатурам (Inno Setup, NSIS, InstallShield,
   MSI/msiexec, WiX Burn, InstallAware, Wise, self-extract).
2. **Строит команду тихой установки** с правильными ключами для каждого движка и
   указанием целевой папки внутри портатива (например, `App\`).
3. **Запускает установку тихо и изолированно**: пользовательские каталоги
   (`APPDATA`, `LOCALAPPDATA`, `TEMP`, `USERPROFILE`, `PROGRAMDATA`) на время
   установки перенаправляются внутрь портативной папки.
4. **Захватывает изменения реестра и сортирует их**: снимок HKCU/HKLM\Software
   до и после установки. Разница делится на три группы — настройки программы
   (едут в портатив), интеграция с оболочкой (по желанию) и следы установки
   (в портатив не попадают никогда, см. «Автономность» ниже).
5. **Проверяет результат установки**. Если установщик проигнорировал целевую
   папку, ищет созданную программу в перенаправленном `LocalAppData`, новых
   каталогах `Program Files` и значениях `InstallLocation`, затем переносит её
   в `App/`. Если exe так и не найден, операция завершается ошибкой и сломанный
   `Launch.bat` не создаётся.
6. **Находит главный exe** установленной программы и **собирает зависимости**
   (папки с `.dll` добавляются в `PATH` лончера).
7. **Генерирует портативный лончер** (`Launch.bat`, `LaunchHidden.vbs`,
   `launcher_config.json`, опционально `launcher.py`), который при каждом
   запуске воссоздаёт изолированное окружение, подставляет настройки и
   запускает программу.
8. **Убирает следы установки с вашего ПК**: запись из списка «Установленные
   программы», созданные ярлыки и изменения реестра откатываются, поэтому
   компьютер-сборщик остаётся чистым.

Итоговая структура портатива:

```
MyApp_Portable/
├─ App/                    ← установленная программа
├─ PortableData/          ← все пользовательские данные (AppData, Temp, реестр)
├─ Launch.bat            ← запуск в изолированном режиме (чистый ASCII)
├─ LaunchHidden.vbs      ← то же самое, но без окна консоли
├─ launcher_config.json  ← параметры лончера
├─ portable.reg          ← настройки программы (HKCU), путь — маркером
├─ portable_machine.reg  ← настройки HKLM (если были)
├─ cleanup_host.reg      ← откат следов установки на ЭТОМ ПК
├─ install.log           ← журнал установщика (если поддерживается)
├─ portablizer.log       ← журнал создания и диагностики
└─ README_PORTABLE.txt
```

## Автономность и переносимость с флешки на флешку

Портатив рассчитан на сценарий «скопировал папку на флешку — работает на любом
ПК», без установки и без прав администратора.

**Программа не попадает в список «Установленные программы» чужого ПК.**
Записи ветки `Uninstall` (именно она формирует этот список), автозапуск `Run`,
данные Windows Installer и службы классифицируются как *следы установки* и в
портатив **не переносятся никогда** — переносятся только собственные настройки
программы. Если бы этого разделения не было, портатив при первом же запуске
«устанавливал» бы себя на каждый новый компьютер.

**Компьютер, на котором вы делаете портатив, тоже остаётся чистым.** Тихая
установка — это всё-таки установка, поэтому после сборки Portablizer:

* удаляет программу из списка «Установленные программы»;
* удаляет созданные установщиком ярлыки (меню «Пуск», рабочий стол);
* возвращает изменённые ключи реестра к прежним значениям.

Полный откат сохраняется в `cleanup_host.reg` — если прав не хватило, файл
можно запустить вручную от имени администратора. Поведение отключается галочкой
«Убрать следы установки с этого ПК».

**Запуск ничего не оставляет на чужой машине.** Если программе нужны записи
реестра, лончер сначала сохраняет прежнее состояние чужого ПК, затем
подставляет настройки из портатива, а при выходе выгружает изменения обратно в
папку и возвращает реестр как было. Абсолютный путь папки хранится маркером
`@@PORTABLE_ROOT@@`, поэтому смена буквы диска или компьютера ничего не ломает.
Ассоциации файлов и COM по умолчанию не переносятся (галочка «Переносить
ассоциации файлов и COM»).

### Почему `Launch.bat` раньше «мигал и закрывался»

cmd.exe читает .bat не построчно, а блоками, запоминая **байтовое** смещение.
Прежний лончер вызывал `chcp 65001` и содержал русский текст в комментариях —
после смены кодовой страницы смещение «съезжало», интерпретатор начинал читать
команды с середины строки и молча завершался, не дойдя до запуска программы.

Теперь `Launch.bat` **строго ASCII** и не вызывает `chcp`; генератор проверяет
это и падает с ошибкой, если не-ASCII символ просочился в шаблон. Имена файлов
с кириллицей подставляются не литералом, а маской `?`, которую cmd раскрывает
через файловую систему.

Ключи запуска:

```bat
Launch.bat                      :: обычный запуск
Launch.bat --nopause            :: не ждать нажатия клавиши
Launch.bat --no-registry        :: вообще не трогать реестр
Launch.bat --keep-registry      :: оставить настройки в реестре после выхода
Launch.bat --reset              :: забыть сохранённые настройки
Launch.bat --help               :: справка
Launch.bat -- --arg1 --arg2     :: передать аргументы самой программе
```

## Запуск из исходников

```bash
pip install -r requirements.txt
python app.py
```

> На Linux/macOS приложение запускается и полностью работает интерфейс, но
> реальная тихая установка и захват реестра выполняются **только под Windows**
> (на других ОС — безопасный демо-режим).

## Сборка Windows-исполняемого файла (.exe)

### Вариант A — локально на Windows
Нужен установленный Python 3.10+ (с python.org, галочка «Add to PATH»):

```bat
build.bat
```

Результат: `dist\Portablizer.exe` — один самодостаточный файл без консоли.

### Вариант B — через GitHub Actions (без своего Windows)
В репозитории настроен workflow `.github/workflows/build-windows.yml`. Он
собирает `Portablizer.exe` на настоящем раннере `windows-latest` при каждом
push в ветку `arena/**` и публикует артефакт **Portablizer-windows-x64**.

Скачать готовый exe:
1. Вкладка **Actions** → последний запуск **Build Windows EXE**.
2. Раздел **Artifacts** → **Portablizer-windows-x64**.

Или через CLI: `gh run download --name Portablizer-windows-x64`.

## Рекомендации по использованию

- Запускайте Portablizer **от имени администратора** — это нужно и для снимка
  ветки `HKLM`, и для установки программ с повышенными правами, и для полной
  очистки следов установки с вашего компьютера.
- Проверить готовый портатив проще всего так: скопируйте папку на флешку,
  откройте её на другом ПК и запустите `Launch.bat`. Программы не должно быть
  в списке «Установленные программы» этого компьютера ни до, ни после запуска.
- Если установщик не распознан или после установки в `App/` нет exe, проверьте
  `portablizer.log`/`install.log` и задайте ключи вручную в поле **«Доп.
  аргументы установки»**. Portablizer больше не считает пустую `App/` успешным
  результатом и не создаёт в таком случае заведомо сломанный `Launch.bat`.
- MSI обрабатывается административной распаковкой (`msiexec /a`) в `App/`, а не
  обычной системной установкой (`/i`).
- Полная виртуализация реестра/файловой системы (как в ThinApp/Cameyo) не
  выполняется: применяется практичная модель — перенаправление пользовательских
  каталогов + импорт захваченного `.reg`. Это покрывает подавляющее большинство
  обычных приложений.

## Архитектура

```
portablizer/
├─ core/
│  ├─ detect.py       ← определение типа установщика по сигнатурам
│  ├─ silentargs.py   ← построение ключей тихой установки по движку
│  ├─ registry.py     ← снимок/diff реестра → .reg (только Windows)
│  ├─ launcher.py     ← генерация Launch.bat / launcher.py / config
│  ├─ portablizer.py  ← оркестратор всего процесса
│  └─ logutil.py      ← потокобезопасный логгер
└─ gui/
   ├─ main_window.py  ← главное окно (PySide6)
   ├─ worker.py       ← фоновый поток (QThread)
   └─ style.py        ← тёмная тема (QSS)

tests/
├─ batsim.py              ← мини-интерпретатор cmd.exe
└─ test_portablizer.py    ← тесты, в т.ч. реальное исполнение Launch.bat
```

### Тесты

```bash
python -m unittest discover -s tests -v
```

`tests/batsim.py` — интерпретатор подмножества cmd.exe (метки, `goto`/`call`,
`if`/`for`, подстановка переменных, `%~dp0`). Он **исполняет** сгенерированный
`Launch.bat` и проверяет, что тот доходит до запуска программы. Именно так
ловится исходная регрессия: старый лончер с `chcp` и кириллицей интерпретатор
отвергает, новый — проходит на путях с пробелами, `&` и любой буквой диска.
